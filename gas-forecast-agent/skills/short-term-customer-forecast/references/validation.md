# 参数校验职责

## 总原则

采用两层校验：智能体在调用前检查对话信息是否完整，Java MCP和Business Service执行最终强制校验。即使智能体认为参数正确，也必须接受Java返回的业务结果；任何调用方都不能绕过Java校验。

## 智能体前置检查

智能体只检查能够从用户表达和实时工具Schema直接判断的内容：

| 检查项 | 不满足时的动作 |
|---|---|
| 用户意图是训练还是预测 | 询问用户需要训练模型还是预测用气量 |
| 单客户操作提供了客户名称或编码 | 询问客户名称或编码 |
| 客户解析结果唯一 | 多候选时展示候选并等待选择 |
| `RECENT` 模式提供 `trainingPeriods` | 询问使用最近多少天的数据 |
| `RANGE` 模式同时提供训练开始和结束日期 | 询问缺失的一端日期 |
| 日期文本符合 `yyyy-MM-dd` | 请用户按正确格式重述 |
| 预测结束日期不早于用户给出的开始日期 | 请用户修正冲突日期 |
| 批量训练或预测获得明确确认 | 说明范围和影响，等待确认 |
| `forceRetrain: true` 获得明确确认 | 说明将创建新训练并等待确认 |
| 时间粒度为日 | 月度和冬季请求退回会话路由 |

智能体不得为了补齐参数自行编造客户编码、日期、范围或确认状态。允许服务端提供默认值的字段可以省略，但应在任务受理结果中向用户说明最终采用值。

## Java最终校验

下列事项依赖权限、数据库、模型配置或实时任务状态，只能由Java作为最终裁决：

- 用户身份、数据权限以及会话归属。
- 客户、地区和行业是否真实存在并属于可操作范围。
- 客户是否具备短期预测条件，历史日销量是否足够且有效。
- 用户指定训练区间内是否存在足够数据。
- 预测开始日期是否不早于客户最新有效销量日期的下一天。
- 模型实际允许的最大预测周期。
- 是否存在可复用的成功模型，以及是否需要自动训练。
- 幂等键是否已创建业务任务，是否存在重复提交。
- 任务、训练批次和预测批次的真实状态。
- 失败任务是否允许等待、恢复或创建新批次。

## Java校验失败的推荐返回

工具失败结果应让智能体能够确定下一步，而不是只返回“参数错误”：

```json
{
  "success": false,
  "status": "NEED_INFORMATION",
  "errorCode": "FORECAST_HORIZON_EXCEEDED",
  "message": "当前客户模型最多支持预测60天",
  "retryable": false,
  "data": {
    "field": "forecastHorizon",
    "providedValue": 90,
    "maximumValue": 60,
    "reason": "当前模型最大预测周期为60天",
    "nextAction": "请用户将预测天数调整为1到60天"
  }
}
```

推荐稳定字段：`status`、`errorCode`、`message`、`retryable`、`data.field`、`data.reason`、`data.nextAction`；存在取值范围时增加 `allowedValues` 或最小最大值，实体存在歧义时增加 `candidates`。

## 智能体处理状态

| 工具状态 | 智能体动作 |
|---|---|
| `NEED_INFORMATION` | 根据 `field` 和 `nextAction` 向用户补问，不重复询问已有参数 |
| `NEED_CONFIRMATION` / `CONFIRMATION_REQUIRED` | 说明实际范围和影响，等待用户明确确认 |
| `WAITING_TRAINING` | 保存训练批次号并查询训练进度 |
| `EXECUTING` | 保存任务号或批次号，报告当前进度 |
| `COMPLETED` | 获取并解释实际结果 |
| `FAILED` 且可重试 | 先查询真实任务状态，再按照恢复建议处理 |
| `FAILED` 且不可重试 | 告知具体原因及用户可以修正的条件 |
