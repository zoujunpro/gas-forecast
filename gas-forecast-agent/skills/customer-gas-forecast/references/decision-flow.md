# 预测决策

## 请求分类

| 用户目标 | 下一步 |
| --- | --- |
| 创建新的客户日预测 | 补齐实体和周期后调用 `forecast_start` |
| 查询某批次进度 | 调用 `forecast_status_get` |
| 查询统一任务进度或步骤 | 调用 `task_status_get` 或 `task_steps_get` |
| 查询指定批次结果 | 先确认状态；成功后调用 `forecast_result_get` |
| 查询某客户最新预测 | 唯一解析客户后调用 `forecast_latest_get` |
| 查询某客户预测历史 | 唯一解析客户后调用 `forecast_history_get` |
| 明确要求训练或重训 | 切换到 `model-training-management` |
| 只是查询客户资料 | 切换到 `business-data-query` |

## 单客户预测

1. 没有标准客户编码时调用 `customer_search`。
2. `UNIQUE`：保存标准客户、地区和行业信息。
3. `MULTIPLE`：完整展示候选的名称、编码、地区和行业，等待用户选择。
4. `NOT_FOUND`：停止，请用户修正名称或补充地区、行业。
5. 参数齐全后调用一次 `forecast_start`。
6. 获得任务号或批次号后结束本轮，不立即查询状态，不再次提交。

## 场景与默认值

| 用户场景 | `agentCode` | `forecastFrequency` | 默认周期 |
| --- | --- | --- | --- |
| 短期客户预测 | `short-term` | `DAILY` | 30天 |
| 月度销量预测 | `monthly-sales` | `MONTHLY` | 12个月 |
| 冬季保供预测 | `winter-supply` | `TENDAY` | 18旬 |

- 用户明确指定周期时使用用户值；未指定时允许后端使用上述默认值，并在受理结果中说明。
- 用户要求的粒度与场景不一致时，不自行改成其他场景，应说明冲突并请用户选择。

## 批量预测

1. 解析地区和行业范围。
2. 向用户复述范围、周期，以及将为多个客户创建任务。
3. 获得明确确认后才允许调用 `forecast_start`。
4. 结果必须分别说明总数、已受理数、失败数、批次号和逐客户失败原因。
5. 部分成功不能描述为全部成功；不得为了失败客户重复提交整个批次。

## 查询结果

- 只有真实状态为成功时才获取并展示预测点。
- 返回点位时保留原始日期、数值和单位。
- 未返回预测点时明确说明“任务已完成但暂无可展示明细”或工具给出的真实原因。
- 预测值是模型输出，不得表述为未来实际用量保证。

## 编号识别

用户只提供一个编号且不能确定是统一任务号、训练批次号还是预测批次号时，先调用
`business_reference_resolve`。根据真实类型选择状态或结果工具，不根据编号外观猜测。
