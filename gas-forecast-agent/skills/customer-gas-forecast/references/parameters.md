# 参数与实体

实时 MCP JSON Schema 是参数名称、类型和必填项的最终依据。不得传递 Schema 未声明的参数。

## 参数来源

- `customerCode` 必须来自当前页面绑定数据、`customer_search` 唯一结果或用户从候选项中的明确选择，禁止模型编造。
- `regionCode`、`industryCode` 必须来自绑定数据或对应搜索工具结果。
- `forecastBatchNo`、`taskNo` 必须来自工具结果或用户明确提供的编号。
- 本轮明确提到的新客户、地区或行业覆盖会话记忆；不得把旧客户编码套给新客户名称。
- 用户说“城市燃气”“城镇燃气”时规范为“城燃”，但编码仍通过 `industry_search` 获取。
- 页面 metadata 是用户已选定的范围，优先级高于从自然语言推断的值。

## 创建预测

- 单客户预测至少需要唯一的客户编码；批量预测至少需要地区、行业或明确客户集合之一。
- 短期、月度销量、冬季保供分别使用 `short-term`、`monthly-sales`、`winter-supply`。
- 对应预测粒度分别为 `DAILY`、`MONTHLY`、`TENDAY`。
- 用户给出开始和结束日期时保留两端日期，结束日期不得早于开始日期。
- 用户给出预测周期时传 `forecastHorizon`。未说明周期时省略该参数，由后端采用场景默认值，并在受理结果中说明最终值。
- 用户要求重新训练后预测时使用工具支持的训练偏好参数；不得把普通预测擅自升级成重训。
- `idempotencyKey` 由控制器生成或复用，模型不得创造不同幂等键以重复提交。

## 必须追问

- 没有任何客户或批量范围。
- 客户搜索返回多个候选且用户尚未选择。
- 用户同时给出互相冲突的客户、地区或行业。
- 日期范围自相矛盾。
- 用户明确提到训练但无法判断是“缺少模型时自动训练”还是“无条件重新训练”，且两者会创建不同任务。

追问只询问当前缺失或冲突的字段，不重复询问已经确认的信息。
