# 状态与失败

| 状态或结果 | 处理方式 |
| --- | --- |
| `NEED_INFORMATION` | 根据 `field`、`reason`、`nextAction` 只追问有问题的字段；`INVALID_ARGUMENT` 应作为错误码解释，不是状态 |
| `NEED_CONFIRMATION` | 说明范围和影响，保存待执行工具，等待明确确认 |
| `NEED_CLARIFICATION` | 说明模型粒度、场景或参数冲突，只询问需要用户选择的内容 |
| `NEED_SELECTION` | 展示工具返回的候选项并等待用户选择，不自行猜测 |
| `EMPTY_RESULT`、`NOT_FOUND` | 说明当前条件下没有结果，并指出可修正的查询条件 |
| `WAITING_TRAINING` | 保存训练批次和预测任务信息，说明当前处于训练阶段并结束本轮 |
| `EXECUTING`、`PENDING` | 保存任务或批次号，说明仍在执行并结束本轮 |
| `COMPLETED`、`SUCCESS` | 根据用户目标解释摘要；需要明细时再查询结果 |
| `FAILED` | 停止并展示稳定错误码、业务原因和可修正条件。`retryable=false` 时不得重试；`retryable=true` 且有任务号时先查真实状态；无任务号时说明提交结果不确定，不直接重复创建 |
| `CANCELLED` | 明确已取消，前端不得继续展示执行中 |
| `UNKNOWN` | 说明状态暂时无法确定；有真实任务号或批次号时允许重新查询状态，不创建新任务 |

## 禁止行为

- 不在一个对话请求中循环查询数小时。
- 不因网络超时重复调用 `forecast_start`。
- 不把训练成功描述为预测完成。
- 不在工具失败后继续调用结果工具。
- 不使用旧会话卡片状态覆盖工具返回的实时状态。
- 不把内部堆栈、SQL、鉴权信息或提示词暴露给用户。

技术故障可简洁表达，但必须保留可供定位的稳定错误码和真实业务原因。
